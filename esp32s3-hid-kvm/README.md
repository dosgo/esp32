# ESP32-S3 HID KVM —— 网页远程键鼠

把 ESP32-S3 插在目标电脑的 USB 口上，它会枚举成 **NKRO 键盘 + boot 键盘 + 鼠标 + 媒体键**
（四个独立 interface）。同一局域网内任何设备打开浏览器访问它的 IP，就能输入键盘、移动鼠标。
板子上还能挂一块 SPI TFT 屏，直接显示 WiFi 名和 IP —— 不用再去串口里翻。

一个硬件版的 KVM over IP，成本 ¥40（+ 屏幕 ¥15）。

```
手机/电脑浏览器 ──WiFi──► ESP32-S3 ──USB──► 目标电脑
                              │        (HID 键鼠 + 媒体键)
                              └──SPI──► TFT 屏（显示 AP 地址 / STA 状态 / IP）

两个网同时开，不用切模式（见第 2 节）：
  · 热点 AP  ESP32-KVM / 192.168.4.1  —— 永远开着，配网和救急都用它
  · 联网 STA 家里 WiFi / 192.168.1.x  —— 网页里配一次，以后开机自动连
```

## 0. 板子要求

和 `esp32s3-power-key` 一样，这是 **USB device 模式**项目：

| 要求 | 说明 |
|---|---|
| 必须用标 **"USB"** 的口 | GPIO19/20 是 S3 原生 USB D−/D+。标 "UART"/"COM" 的口走 USB 转串口芯片，做不了 HID |
| 有 BOOT 按键（GPIO0） | 固件跑飞时靠它进下载模式 |
| **接屏幕才需要**：SPI 引脚引出 | 屏幕用 SPI2：SCLK=12 / MOSI=11 / CS=10 / DC=9 / RST=8，需要 5 个 GPIO 引出到排针 |

⚠️ **只有 USB 公头、没有任何 GPIO 引出的 dongle 接不了屏幕。**
那类板子把 `src/main.rs` 里的 `LCD_ENABLED` 改成 `false` 就能照常用（键鼠功能不受影响），
只是看不到 IP —— 得靠串口或 `tools/netlog_listen.py` 拿地址。

## 1. 它和 power-key 项目的区别

| | `esp32s3-power-key` | **本项目** |
|---|---|---|
| HID 用途 | 系统控制（睡眠/唤醒） | 键盘 + 鼠标 |
| 控制入口 | Blinker App（走公网 MQTT） | **网页**（局域网直连） |
| 依赖外网 | 是 | **否**，断网也能用 |

## 2. 配置

`src/main.rs` 顶部：

```rust
const USE_STATIC_IP: bool = false;                          // 想固定 IP 就改 true
const STATIC_IP: Ipv4Address = Ipv4Address::new(192, 168, 1, 60);
const GATEWAY_IP: Ipv4Address = Ipv4Address::new(192, 168, 1, 1);

const LCD_ENABLED: bool = true;   // 没接屏幕改 false
```

**WiFi 账号密码不用写进代码** —— 连热点在网页里配（见 2.0）。

## 2.0 网络：热点（AP）+ 联网（STA）**同时开**，不用切模式

上一版要按 BOOT 在「联网 / 热点」之间二选一，这版不用了：

```
           ┌── 热点 ESP32-KVM ──► 192.168.4.1  （永远开着：配网、救急）
ESP32-S3 ──┤
           └── 家里 WiFi ──────► 192.168.1.x   （配过就自动连，可选）
```

- **热点永远开**：`ESP32-KVM`，地址固定 `192.168.4.1`，任何时候都能连回来
- **联网是可选的**：没配过就只走热点；配过开机自动连，连上后局域网里用它的 IP
  也能打开控制页
- **两个网各跑一份 web server**：连热点能用，连家里 WiFi 也能用
- ESP32-S3 硬件支持 AP+STA 并发（esp-radio 的 `Config::AccessPointStation`），
  代价是热点信道会跟着 STA 走，这是芯片的限制，不影响使用

热点名 / 密码 / 地址在 `src/store.rs`：

```rust
pub const AP_SSID: &str = "ESP32-KVM";
pub const AP_PASSWORD: &str = "kvm12345";   // 留空 = 开放网络；否则必须 8~63 字符
pub const AP_IP: Ipv4Address = Ipv4Address::new(192, 168, 4, 1);
```

> ⚠️ 如果你家路由器网段正好是 `192.168.4.x`，把 `AP_IP` 改成别的（比如 `192.168.71.1`），
> 否则两个网段撞车，STA 那边会不通。

### 怎么配网（第一次用 / 换 WiFi）

1. 手机或电脑连热点 **`ESP32-KVM`**（密码 `kvm12345`）
2. 浏览器打开 **http://192.168.4.1** —— 打开就是键盘控制页
3. 点顶栏右边的 **「WiFi 设置」**（或直接开 `/setup`）
4. 填家里 WiFi 的名字和密码 → **保存并连接**
5. 等 10~20 秒，页面上「联网」变成 **已连接** 并显示局域网 IP

账号密码写进 **flash（`0x9000`）**，掉电不丢，下次开机自动连。

### 恢复出厂设置

两种方式，效果一样 —— **清空整个配置区（16KB，`0x9000`~`0xD000`）并重启**，
之后回到「只有热点、没配过网」的初始状态：

| 方式 | 操作 |
|---|---|
| 板子上 | **长按 BOOT 键 3 秒**（按住 1.5 秒后屏幕会提示 `hold: factory reset`） |
| 网页 | 打开 `/setup` → 最下面「恢复出厂设置」→ 确认 |

热点名和密码是编译期常量，恢复出厂后仍是 `ESP32-KVM` / `kvm12345`。

### 热点侧额外跑的两个服务

- `esp-hal-dhcp-server`（[外部 crate]）—— **必须**。embassy-net 只有 DHCP *客户端*，
  没有服务端；没它手机连上热点会一直卡在「正在获取 IP 地址」。
- `src/dns.rs`（自己写的迷你 DNS）—— 把所有域名都解析到 `192.168.4.1`。
  手机连上没外网的热点后会做「俘虏门户」探测（iOS 访问 captive.apple.com、
  安卓访问 connectivitycheck.gstatic.com），没人应答就可能判定无网络并断开。
  把域名指回自己之后，HTTP 服务对**任意路径**都返回控制页面，
  手机就会弹「登录到此网络」，点进去就是键盘页面。
  顺带在这里数一下见过几个不同 IP，就是屏幕右上角的设备数。

## 2.1 屏幕接线

| TFT 屏引脚 | ESP32-S3 | 说明 |
|---|---|---|
| VCC | 3.3V（或 5V，看屏） | 多数 SPI 屏模块带电平转换，5V 也行 |
| GND | GND | |
| SCL / SCK | **GPIO12** | SPI 时钟 |
| SDA / MOSI | **GPIO11** | SPI 数据（屏是只写的，MISO 不用接） |
| CS | **GPIO10** | 片选 |
| DC / RS | **GPIO9** | 数据/命令切换 |
| RES / RST | **GPIO8** | 复位 |
| BL / LED | 3.3V | 背光，直接接 3.3V 常亮；想调光就接个 GPIO |

改引脚在 `src/lcd.rs` 的 `lcd_task()` 参数 + `src/main.rs` 里 spawn 的那一行。

### 换屏幕型号：只改一个数字

不知道自己那块屏是什么型号很正常 —— **改 `src/lcd.rs` 里的 `LCD_MODEL`，挨个试**：

```rust
const LCD_MODEL: usize = 0;
```

| 值 | 驱动 | 分辨率 | 常见尺寸 |
|---|---|---|---|
| **0** | ILI9341 | 240x320 | 2.4 / 2.8 / 3.2 寸（默认，最常见） |
| **1** | ST7789 | 240x240 | 1.14 / 1.3 / 1.54 寸方屏 |
| **2** | ST7789 | 240x320 | 2.0 / 2.4 寸长条屏（很多 ESP32 套件自带这种） |
| **3** | ST7735s | 128x160 | 1.8 寸 |

改完重新编译烧写，看屏幕亮不亮、内容对不对。顺序试 `0 → 1 → 2 → 3`，对了就停。

> mipidsi 初始化成功不代表型号对 —— 型号错了通常表现为**黑屏、花屏或只亮背光**。
> 所以只能靠肉眼判断，这也是为什么做成改一个数字而不是自动探测。

其他调整：`Builder` 那行加 `.color_order(ColorOrder::Bgr)` 修红蓝反色，
加 `.invert_colors(ColorInversion::Inverted)` 修整体反色。
屏幕完全不亮就把 SPI 频率从 20MHz 降到 1MHz 试（`lcd_task()` 里的 `Rate::from_mhz(20)`）。

> 屏幕显示的是 **ASCII 字体**，中文 SSID 会显示成 `?`。这是字体限制，不影响连接。

$env:PATH = "$env:USERPROFILE\.rustup\toolchains\esp\xtensa-esp-elf\bin;$env:PATH"

```powershell

```

## 4. 使用

### 走热点（最省事，推荐先用这个）

1. 烧完后板子插目标电脑的 USB 口
2. 手机/电脑连 WiFi **`ESP32-KVM`**，密码 `kvm12345`
3. 浏览器打开 **http://192.168.4.1** （安卓一般会自动弹「登录到此网络」的通知）
4. **打开就自动连 WebSocket，不用点任何按钮** —— 顶栏状态点变绿即可用
5. 点虚拟键盘上的键 = 目标机收到按键；在上面那块触控区点一下 = 接管鼠标

### 走家里 WiFi（配过网之后）

1. 板子插电脑，等它自动连上你配过的 WiFi（屏幕上 LINK 变 `connected`）
2. **屏幕上直接看局域网 IP**（没屏幕就看串口 / `python tools/netlog_listen.py`）
3. 浏览器打开 `http://192.168.1.x`，之后操作完全一样

两个地址**同时可用**：连热点用 `192.168.4.1`，连家里 WiFi 用局域网 IP。

屏幕显示：右上角是连进热点的设备数，下面依次是
MODE（`AP+STA`）/ AP 地址 / STA 名字 / LINK（STA 状态）/ IP（STA 地址）/
USB 枚举状态 / 控制端数量，底部一条热点地址。

### 页面功能

页面分三块：**顶栏**（状态 + 开关）、**鼠标触控区**、**虚拟全键盘**（104 键 + 小键盘）。

| 操作 | 效果 |
|---|---|
| **点虚拟键盘的键** | 按下即发送，松开即释放 —— 不需要目标机装任何东西 |
| 点 **Ctrl / Shift / Alt / Win** | 「粘住」：点一下保持按下（高亮），再点松开 |
| 粘住修饰键后按普通键 | 组合键生效，按完**自动松开**修饰键（想一直按住就开「锁定修饰键」） |
| 点触控区 | 锁定鼠标指针（Pointer Lock），此后移动鼠标全部发给目标机 |
| 鼠标锁定时再点一下 | 解锁，交还控制权（按 **Esc** 同样解锁） |
| 未锁定时在触控区拖动 | 也能移鼠标（手机上、不支持锁定的浏览器用这个） |
| 左/中/右键按钮 | 按住 = 按下，松开 = 释放（方便拖拽） |
| ▲滚 / ▼滚 | 滚轮 |
| 「隐藏键盘」 | 键盘区收起，屏幕全给触控区（手机竖屏时有用） |
| 「本机键盘」 | 把你**电脑上**的物理键盘也转发过去（默认关，避免你打字被误发） |
| 「释放所有按键」 | 强制发一次全 0 报告，解卡键 |
| 切到别的窗口 | 自动释放所有按键（防卡键） |
| 手机浏览器 | 触控区单指移动 / 双击=左键 / 双指上下滑=滚轮 |
| 音量 / 播放 / 亮度等媒体键 | 键盘上方那排按钮，走 Consumer Control 接口 |
| **「BIOS 模式」按钮** | 切到 6KRO boot 报告，进 BIOS / 无驱动环境用 |

> **一个浏览器限制**：指针锁定期间光标是隐藏的，鼠标事件全被触控区吃掉，
> 所以「锁着鼠标时点键盘」第一下只会解锁，第二下才按到键。
> 按 Esc 解锁后再点键盘就不会有多余的一下。

## 5. 设计要点

### 全键盘：四个独立 interface

| # | interface | 报告 | 用途 |
|---|---|---|---|
| ① | **NKRO 键盘** | 20 字节（1 修饰键 + 19 字节 bitmap） | 日常使用，**任意多键同按** |
| ② | boot 键盘 | 8 字节标准 | BIOS / 无驱动环境（点「BIOS 模式」切换） |
| ③ | 鼠标 | 4 字节 | 相对位移 + 滚轮 |
| ④ | Consumer Control | 2 字节 | 音量、播放暂停、亮度等媒体键 |

**为什么要四个而不是一个复合设备带 Report ID**：boot protocol 只认「单报告、
无 Report ID」的设备，复合写法 BIOS 会认不出来。KVM 场景必须能进 BIOS。

代价是 Windows 设备管理器里会看到多个 HID 设备，这是正常的
（不发数据的那个不会产生输入，不会重复触发）。

#### NKRO 和 BIOS 模式为什么要切换

NKRO 用 bitmap 报告（152 位），**同时按多少个键都不冲突**。但 boot protocol 下
主机只认固定的 8 字节报告，bitmap 发给 BIOS 它是读不懂的。反过来 6KRO 报告在任何
系统都能用，只是同按超过 6 个键会丢。

所以做成网页上一个开关：**日常 NKRO，要进 BIOS 时点一下切过去**。
切换时固件会自动把两个键盘接口都松开，不会卡键。

#### 媒体键不在键盘 usage page 里

音量、播放暂停、亮度这些是 **Consumer Control（Usage Page 0x0C）**，
不在标准键盘的 0x07 page 里 —— 混在键盘描述符里根本发不出去，必须单独开一个 interface。
这是「全键盘」最容易漏掉的一块。

### 为什么鼠标用相对位移

绝对位移（像数位板那样）需要知道目标屏幕分辨率，而且多显示器下坐标映射很麻烦。
相对位移是 boot mouse 的标准做法，BIOS 和所有系统都认，也不用管分辨率。

### 键鼠状态全部由浏览器维护

ESP32 端**零状态管理**。浏览器自己维护「当前按着哪些键」（usage 集合 + 修饰键位图），
每次变化把完整状态发过来。所以：

- 网络丢包不会导致卡键（下一次状态会覆盖）
- 切窗口 / 失焦时浏览器主动发全 0
- 固件端不需要超时逻辑

### 线协议

WebSocket 文本帧，空格分隔，便于调试：

```
n <40位hex>                   NKRO 键盘报告（20 字节）
k <mod> <k1..k6>              boot 键盘报告（BIOS 模式）
m <btn> <dx> <dy> <wheel>     鼠标（相对位移，有符号）
c <usage>                     媒体键，usage=0 表示松开
b <0|1>                       切 BIOS 模式
r                             释放所有键
_p                            心跳（20s 一次）
```

mod 位图：bit0 LCtrl / bit1 LShift / bit2 LAlt / bit3 LGUI / bit4 RCtrl / bit5 RShift / bit6 RAlt / bit7 RGUI

常用媒体键 usage：0xE2 静音 / 0xE9 音量+ / 0xEA 音量− / 0xCD 播放暂停 /
0xB5 下一曲 / 0xB6 上一曲 / 0x6F 亮度+ / 0x70 亮度−

### 为什么自己写 HTTP + WebSocket

`picoserve` 这类框架带 proc-macro / serde，且依赖 Rust 2024 edition，API 版本动荡。
这里只需要几个路由（`/ws` + 配网的 `/setup` `/save` `/status`），自写反而更少出编译问题，且完全可控。

## 6. 代码结构

| 文件 | 作用 |
|---|---|
| `src/hid.rs` | 4 个 HID 报告描述符：NKRO 键盘 / boot 键盘 / 鼠标 / Consumer Control |
| `src/store.rs` | STA 账号密码写进 flash（`0x9000`）持久化 + 热点参数常量 + 恢复出厂（擦 16KB 配置区） |
| `src/dns.rs` | 热点模式的迷你 DNS（把所有 A 查询解析到自己，配合俘虏门户探测；顺带数设备数） |
| `src/lcd.rs` | SPI TFT 驱动（`mipidsi` + `embedded-graphics`），显示 AP 地址 / STA 状态 / IP / 状态 |
| `src/web.rs` | 极简 HTTP + WebSocket 服务器（no_std，含 SHA1 + base64 握手 + 配网路由） |
| `src/main.rs` | USB device 初始化 + WiFi(AP+STA 双栈) + DHCP/DNS + 两个 web server + HID 事件队列 |
| `src/netlog.rs` | 日志经 UDP 广播到 4444（无独立串口时用它看日志） |
| `index.html` | 控制页面，编译期内嵌进固件（`include_str!`），无需文件系统 |
| `setup.html` | 配网表单页，同样内嵌进固件 |
| `tools/netlog_listen.py` | 电脑上接收网络日志 |
| `firmware-kvm.bin` | 已编译镜像 |

## 7. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 设备管理器没多出 HID 设备 | 插错口了，换标 "USB" 的那个 |
| 网页打不开 | 先确认拿到 IP（看串口 / netlog）；再确认电脑和 ESP32 在同一网段 |
| 手机连上热点后一直「正在获取 IP 地址」 | DHCP 服务没起来。看日志有没有 `[dhcp] 启动：` |
| 手机提示「无互联网」并自动断开 | 关掉手机的「自动切换网络 / 网络助理」；DNS 那块看 `src/dns.rs` |
| 配网保存后一直连不上 | 名字/密码错了，或路由器是 5G 频段（ESP32-S3 只支持 2.4G）。回 `/setup` 重填 |
| 配网页面打不开 | 确认连的是 `ESP32-KVM` 这个热点；直接访问 http://192.168.4.1/setup |
| 忘了配过哪个 WiFi / 想重配 | **长按 BOOT 3 秒恢复出厂**并重启；或连热点直接重新配一次（不恢复也行） |
| 恢复出厂后还是连不上老 WiFi | 说明配置没擦掉：看日志有没有 `[boot] 长按 3000ms -> 恢复出厂设置` |
| 长按 BOOT 没反应 | BOOT 必须接到 GPIO0；有些板子按键标的是 `BOOT`/`IO0`/`FLASH` |
| STA 连上了但局域网打不开页面 | 家里网段是不是也是 192.168.4.x？改 `src/store.rs` 的 `AP_IP` |
| 连上了但键鼠没反应 | 检查是否点了「开始控制」（指针锁定）。键盘不需要锁定，鼠标需要 |
| 鼠标乱飘 | 指针锁定没生效。点一下页面中间区域重试 |
| 某个键卡住 | 点「释放所有按键」 |
| BIOS 里鼠标不动 | 正常：boot protocol 忽略第 4 字节滚轮，但移动本身是支持的 |
| **BIOS 里键盘没反应** | 先点「BIOS 模式」再进。NKRO bitmap 报告 BIOS 读不懂 |
| 媒体键（音量）没反应 | 目标机音量键走 Consumer Control，检查是不是被系统的快捷键拦截了 |
| **屏幕全黑 / 全白** | 先看背光（BL 接 3.3V）；再把 SPI 频率降到 1MHz 试 |
| 屏幕亮但显示错位 / 花屏 | 型号不对，改 `src/lcd.rs` 里的 `Builder::new(...)` 和 `display_size` |
| 屏幕颜色发红发蓝 | 加 `.color_order(ColorOrder::Bgr)`；整体反色加 `.invert_colors(...)` |
| 日志报 `[lcd] 初始化失败` | 接线松了，或 CS/DC/RST 接错脚。固件会跳过屏幕继续跑键鼠 |

## 8. 已知限制

- **只能控制一个目标机**（一块 ESP32 插一台电脑）
- **画面回传没有** —— 这是纯 HID 方案，看不到屏幕。要画面得加视频采集卡（HDMI→USB），
  那是另一个量级的项目
- **屏幕只显示 ASCII**，中文 SSID 显示成 `?`（字体限制，不影响连接）
- BIOS 模式下退回 **6KRO**（boot protocol 的上限）；日常 NKRO 无此限制
- 热点和局域网**各**支持一个浏览器连接（同时最多两个），两边共用同一套 USB HID，
  所以别两边同时敲键盘
- 无认证，局域网内任何人都能控制。别暴露到公网
